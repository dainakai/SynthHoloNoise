# SHNの計算と適用範囲

SHN（SynthHoloNoise）は、背景除去後の実験ホログラムに残る模様と揺らぎを統計モデルにまとめ、新しい乱数で合成してclean画像へ加える手法です。
このページでは、実験画像からプリセットを作る工程と、利用者の画像へノイズを加える工程を定義します。
元の実装名は`addnoise4`、保存モデル名は`experimental_variation_residual_v1`です。

## 入出力と設定

入力は、利用者の生成器が作った2次元のホログラム**強度画像**です。
複素数の光波面や粒子の位置データではありません。
SHNは粒子の散乱と光の伝搬を再計算せず、入力画像に対して信号の明るさに依存しない加算量を作ります。

主設定は、ノイズの形と基準振幅を選ぶ`preset`、全成分の大きさをまとめて変える`strength`です。
乱数シード`seed`は同じ結果の再現に使います。
元カメラの`camera`と時間区間の`variant`は詳細設定です。
各プリセットには2カメラ×2区間の4テンプレートがあるため、プリセットと強度だけで乱数実現まで一意に決まるわけではありません。

`001`から`011`は元の日付を古い順に置き換えた識別子です。
この順番はノイズの強さを表しません。
日付は追跡用のメタデータとして残しています。
同一プリセットの同一テンプレートを選んだ場合、強度0.5は係数を半分、1はそのまま、2は2倍にします。
強度0は入力と全画素一致です。

## 実験画像の選び方

元の調査では、設定ファイルを持ち、BMPが1万枚以上ある系列を対象にしました。
重複コピーを除いて170系列、85カメラ対があり、撮影日は11日でした。
各撮影日について、カメラ対の画像平均と画像標準偏差が、その日の中央値に近いシーンを1つ選びました。
具体的には、2つの特徴を日内の中央値で中心化し、四分位範囲（下限0.25）で割った後、2特徴の二乗平均平方根が最小になるシーンを選んでいます。
これは典型例の選択であり、その日の極端な条件を網羅する選択ではありません。

各シーンの2台のカメラについて、10917枚の系列の約1/3と2/3の位置から256枚ずつ採りました。
区間開始は後述の32フレームの背景推定位置へ合わせています。
例えば2026-07-03の区間は、0始まりで`[3520, 3776)`と`[7136, 7392)`です。
合計は11日×2カメラ×2時間区間＝44テンプレートです。

共通の計測条件はFASTCAM Mini UX100、1024×1024画素、4000 fps、シャッター設定32000、Mono 8-bit保存、pixel gain mode 1です。
撮影日の違いを経験的に含めたモデルであり、異なる装置の校正データを含むものではありません。

## プリセット作成前の背景除去

各背景推定位置の前後64枚を含む129枚から、画素ごとの時間中央値を取ります。
背景を32フレーム間隔で推定し、その間の背景は線形補間します。
その背景を各生画像から引き、次の補正を順に行います。

1. 残差画像の全画素中央値を引きます。
2. 各行の中央値を取り、その行プロファイルの中央値を引きます。標準偏差3画素の1次元ガウスフィルタで平滑化して、各行から引きます。
3. 行補正後の各列の中央値を取り、同様に中心化と平滑化を行って各列から引きます。
4. 背景の平均値から決めた一様な基準輝度を戻し、丸めて0〜255へ収めます。追加の2次元ローパス除去は使いません。

区間処理では、2区間に必要な背景推定位置の平均輝度の中央値を基準輝度にしています。
系列全体で計算した版との既存比較では、基準輝度の推定範囲の違いにより最大1階調、平均絶対差0.1146階調の差がありました。
SHNは、この補正を終えた8-bit画像から残差を学習しています。
利用者はこれらの生の実験画像を準備せず、配布されたプリセットだけでノイズを生成できます。

## 5成分への分解

以下で、`x`は横の画素番号、`y`は縦の画素番号、`t`は区間内のフレーム番号です。
背景補正済み画像を`B_t(y,x)`とします。
256枚の各画素の時間中央値を`M(y,x)`とし、画像全体の中央値を引いたものを、時間的に残る模様`P(y,x)`とします。

```text
M(y,x) = フレームtについての B_t(y,x) の中央値
P(y,x) = M(y,x) − Mの全画素中央値
```

この時間中央値は元コードでは`torch.median`で計算しているため、256個の偶数個データでは中央2値のうち小さい方を返します。
抽出処理を再実装する場合は、中央2値を平均する中央値との違いを保持する必要があります。

| 成分 | 元の配列を作る操作 |
|---|---|
| 広い明暗むら | `P`へ標準偏差32画素の2次元ガウス平滑化を適用 |
| 行の偏り | `P − 広い明暗むら`の各行中央値を、標準偏差3画素で平滑化 |
| 列の偏り | 行の偏りまで引いた残りの各列中央値を、標準偏差3画素で平滑化 |
| 固定模様 | `P`から上の3成分を引いた残り |
| 動的な揺らぎ | 各フレームの`B_t − M` |

行の偏りは同じ行の全列へ加わるので横縞、列の偏りは同じ列の全行へ加わるので縦縞です。
この分解は処理順序に依存します。
各成分を特定の物理現象へ一意に分離したことを意味しません。

## 動的成分の抽出と大きさの推定

各画素について、256枚の時間中央値からの絶対偏差の中央値を計算します。
これを**時間MAD**と呼びます。
画像を128×128画素の領域へ分け、領域内の時間MADの中央値が小さい8領域を選びます。
256枚から等間隔に選んだ8時刻について`B_t − M`を切り出し、64枚の小画像を得ます。
保存前に−127〜127へ制限し、符号付き8-bitへ変換します。

これは粒子通過が少ない領域を選ぶ手順です。
弱い干渉縞や静止に近い粒子まで、完全に排除する処理ではありません。

動的成分の振幅係数は、上の小画像の標準偏差をそのまま使うのではなく、別の計算で求めます。
縦横8画素間隔で抜き出した画素のうち、時間MADが下位50%の画素を選びます。
この画素群で隣接フレーム差`d = B_t − B_(t−1)`を集め、次の式を使います。

```text
σD = median(|d − median(d)|) / (0.67448975 × √2)
```

ここで`σD`は保存される動的成分の係数、単位は8-bitの1階調（DN）です。
独立な正規分布ノイズであれば、隣接差の標準偏差は1枚の標準偏差の√2倍です。
また、正規分布のMADは標準偏差の約0.67449倍です。
この2つの関係を使った換算です。

実際のデータには時間相関があり、分布も厳密な正規分布ではありません。
したがって`σD`は**隣接差から換算した基準係数**です。
実験画像の動的標準偏差やセンサーの読み出しノイズを厳密に測った値ではありません。
例えば正規分布で隣接相関が`ρ`なら、この差分推定値は元の標準偏差の約`√(1−ρ)`倍になります。
元コードには、この相関を使って係数を補正する処理はありません。

時間相関は、同じ静かな画素から時間中央値を引いたベクトルを使います。
隣接フレームのベクトルをそれぞれ`v`と`w`とし、全フレーム対を並べて、正規化内積`dot(v,w)/sqrt(dot(v,v)dot(w,w))`を計算します。
各ベクトルを改めて平均中心化したPearson相関と、定義上完全に同じではありません。

## プリセットに保存するもの

大きさと模様を分けるため、広い明暗むら、行、列、固定模様をそれぞれ平均0、標準偏差1へそろえます。
元の4つの標準偏差は別の係数として保存します。

| 保存配列 | 1テンプレートの形 | 用途 |
|---|---|---|
| 広い明暗むら | 128×128 | 元の1024×1024を面積補間で縮小した模様 |
| 行プロファイル | 1024 | 横縞の模様 |
| 列プロファイル | 1024 | 縦縞の模様 |
| 固定フーリエ振幅 | 1024×513 | 固定模様の2次元実数FFTの絶対値 |
| 動的フーリエ振幅 | 128×65 | 64枚の小画像から得た振幅の平均 |
| 動的分位点 | 257 | 0、1/256、…、1に対応する画素値 |

動的な小画像は、各小画像の平均を引き、全64枚をまとめた標準偏差で割ります。
各小画像に2次元Hann窓を掛けてFFTし、その**振幅の平均**を求めます。
これはパワースペクトルの平均と同じではありません。
分位点は、窓を掛ける前の正規化済み小画像全体から計算します。
固定と動的の振幅スペクトルは最大値1へそろえます。
大半の配列はfloat16、共通の分位点確率はfloat32で保存しています。

モデル構築時の正規化の分母下限は`1e-4`、合成時の再正規化の下限は`1e-5`です。
これらは、ほぼ一定の配列でのゼロ割りを避けるための下限です。

SHNの配布用データは元の配列を44ファイルへ分割しています。
値は再推定せず保持しています。
全体は約41 MB、1テンプレートは約1 MBです。
元の実験残差画像、粒子座標、絶対ファイルパスは配布に含めていません。

## 新しい模様を合成する計算

以後、配列`A`の平均を引いて標準偏差で割る操作を`U(A)`と書きます。

```text
U(A) = (A − mean(A)) / max(std(A), 1e−5)
```

**広い明暗むら`L(y,x)`**は、128×128のテンプレートを入力画像サイズへバイキュービック補間し、0、90、180、270度のいずれかへ回転します。
上下と左右をそれぞれ確率0.5で反転し、縦横にランダムな循環移動を行います。
循環移動では端を越えた部分が反対側へ回ります。
最後に`U`を適用します。

**行の偏り`R(y)`と列の偏り`C(x)`**は、それぞれ保存済みの1次元配列を独立に循環移動し、`U`を適用します。
`R(y)`は行`y`の全画素、`C(x)`は列`x`の全画素へ同じ値を加えます。

**固定模様`F(y,x)`**は、保存した振幅スペクトル`AF`と新しい乱数位相から作ります。
各画素に独立な標準正規乱数を置いた画像を`W`、その2次元実数FFTを`FFT(W)`とします。
位相だけを取り出す配列`phase`と固定模様は次の式です。

```text
phase = FFT(W) / max(|FFT(W)|, 1e−12)  # 各周波数で計算
F = U(inverse_real_FFT(AF × phase))
```

保存する振幅は「どの細かさと方向の模様をどれくらい含むか」を表します。
新しい位相を使うことで、元の固定画像をそのまま貼り付けることを避けます。
同じ系列内では、生成した`L,R,C,F`を保持します。

**動的成分**では、動的振幅スペクトル`AD`と新しいランダム位相から標準化した模様`G_t`を作ります。
`AD`は縦の周波数軸を中心へ移動してから出力の実数FFT格子へ線形補間し、縦軸を元に戻して使います。
正規乱数の位相から作るこの場は正規分布に近いものの、画素分布が厳密に正規分布になる保証はありません。

次に、標準正規分布の累積分布関数`Φ`を適用します。
例えば`Φ(0)=0.5`、`Φ(1.645)≈0.95`です。
得られた確率を保存済みの分位点関数`QD`へ入れ、257点の間を線形補間します。
例えば0.95は実測小画像の95パーセンタイルに対応します。

```text
G_t = U(inverse_real_FFT(AD × 新しいランダム位相))
E_t = U(QD(Φ(G_t)))
```

`E_t`が、そのフレームで新しく作った動的模様です。
最初のフレームでは`D_0=E_0`とします。
それ以降は、前フレームの動的模様`D_(t−1)`と混ぜます。

```text
ρ = clip(保存された隣接相関, 0, 0.9)
D_t = U(ρ D_(t−1) + √(1−ρ²) E_t)
```

これをAR(1)型の更新と呼びます。
`ρ`が大きいほど前の模様が残ります。
負の実測相関は0になるため再現しません。
係数はフレーム当たりであり、別のfpsへ自動換算しません。
元コードではテンプレート変更時に動的状態をリセットします。
SHNでは1つの生成器が1つのテンプレートを担当し、変更時は新しい生成器を作ります。

## 足し合わせと保存

平均0、標準偏差1の各模様へ、保存済みの係数を掛けます。
係数を`σL,σR,σC,σF,σD`、ユーザーの強度を`s`、clean画像を`I_t`とすると、追加量`N_t`と8-bit出力`J_t`は次の式です。

```text
N_t(y,x) = s [σL L(y,x) + σR R(y) + σC C(x) + σF F(y,x) + σD D_t(y,x)]
J_t(y,x) = clip(round(I_t(y,x) + N_t(y,x)), 0, 255)
```

丸めはNumPyの`rint`で、ちょうど半整数の場合は近い偶数を選びます。
`N_t`は丸め前の追加量です。
画面に表示する差分`J_t − I_t`には、整数化とクリッピングの影響が含まれます。
5つの成分間には相関がありうるため、合計の標準偏差は係数の単純な和ではありません。

元コードには成分別の追加倍率もあり、広いむら、行と列、固定、動的の4設定がありました。
参照ベンチマークではすべて1でした。
SHN 1.0の標準APIはこの比率を保ち、成分別配列を返せるようにしています。

## 参照画像の具体的な値

参照されたwide350の画像は、2026-07-03、C002、最初の時間区間、元テンプレートID42、強度0.5です。
SHNではプリセット`011`、カメラ`C002`、区間`001`、テンプレート`043`に対応します。

| 成分 | 保存係数（DN） | 強度0.5を掛けた係数（DN） |
|---|---:|---:|
| 広い明暗むら | 0.08533808 | 0.04266904 |
| 行 | 0.01471724 | 0.00735862 |
| 列 | 0.02018261 | 0.01009131 |
| 固定 | 0.54449898 | 0.27224949 |
| 動的 | 8.38686466 | 4.19343233 |

隣接相関は`ρ=0.43130368`です。
この条件では動的成分が振幅の大部分を占めます。
参照された最初の保存画像の差分は、平均約`0.00001144 DN`、標準偏差`4.21282769 DN`、最小`−28 DN`、最大`31 DN`でした。

同じ元区間の動的小画像64枚を各小画像の平均で中心化すると、全画素標準偏差は`12.1299 DN`でした。
これは保存係数`8.3869 DN`と異なります。
この実測例からも、強度1を「実験の動的標準偏差をそのまま再現する値」と呼ぶことはできません。
SHNは参照ベンチマークとの整合性を保つため、この係数を勝手に補正していません。

## 静止画、動画、カメラ対

静止画では、初期動的成分`D_0`を使えば処理が完了します。
動画では、同じプリセットとテンプレートを保持し、順番に全フレームを処理します。
離れたフレームだけを先に抜き出して連続扱いすると、元の時間相関と異なる結果になります。
強度が0のフレームでもSHNの生成器は乱数と時間を進め、次のフレームとの対応を保持します。

元の学習用スクリプトには、11日を等確率に選ぶモードと日付固定モードがありました。
さらに、日付と強度を系列単位かフレーム単位で選び直せました。
同じファイル名のカメラ対には日付と強度を共通に割り当て、各カメラのテンプレートと乱数場は別々に生成していました。
実測カメラ間の画素ごとのノイズ相関はモデル化していません。

SHNでは、同じプリセットと強度を2つの生成器へ指定し、カメラとシードを別々にすることでカメラ対を扱えます。
独立画像の学習用に日付をランダム化する場合は、11個のプリセットを等確率で選びます。
時系列の途中でプリセットを変えると固定模様も変わるため、安定した撮影系を模擬する動画では系列ごとに固定します。

元のベンチマークは1つの乱数生成器でC001全3000枚、次にC002全3000枚を処理しました。
同じシードでC002の1枚だけを呼び出しても、乱数消費順序が異なるため、その保存画像と画素一致するわけではありません。
同じライブラリ、モデル、シード、設定、入力順序を合わせて再現します。
異なる数値ライブラリの版やCPU/WASM実行間では、浮動小数点の微小差が整数丸めに影響しうるため、バージョンも記録します。

## 確認できていることと制限

モデルの元評価では、残差の12特徴を標準化して比較した日付間距離の中央値が1.331、日内が0.430でした。
比は約3.10です。
これは複数の撮影日を保持する根拠であり、検出精度が3倍になることを示す数値ではありません。
強度だけを変えた24画像の比較では、追加残差RMSの強度に対する直線性の決定係数が0.999993でした。
強度0の24画像は全画素一致でした。
これらは強度制御の確認であり、別装置への有効性や下流の検出性能を保証する試験ではありません。

SHNへの抽出時には、元の実験統計配列の同一性を確認し、元コードによるC001の最初のベンチマーク画像を全画素一致で再生成しました。
ネイティブサイズでは、新APIの追加量もその検証で元コードと完全一致しました。
公開テストには独立に元コードで生成した数値の照合、強度0、強度比例、時間相関、画素値の単位換算を含めています。

適用時には次の限界があります。

1. 背景除去後の加算残差が対象です。生の画像の照明全体や光子検出の物理過程は生成しません。
2. ノイズの大きさはcleanの局所輝度に依存しません。ショットノイズや信号依存の乗算ノイズは別途モデルが必要です。
3. 各成分は平均0です。保存されている元実験の平均輝度は追跡用であり、合成には使いません。
4. 時間中央値や静かな小領域にも弱い粒子縞が残りえます。純粋なセンサーノイズとの完全な分離ではありません。
5. ランダム位相化は、元の局所的な欠陥配置や非定常な構造を維持しません。低周波と行列は変形した実測模様を利用します。
6. 分位点変換と時間混合は、スペクトルと画素値分布の両方への厳密一致を保証しません。
7. 代表シーンは1日1個です。日内の極端条件をすべて含みません。
8. 任意サイズへの補間は画素空間での近似です。物理的な画素サイズ、視野、fps、露光の変更を自動で校正しません。
9. 8-bitから別値域への換算は振幅の単位変換です。12-bitや16-bitセンサーの量子化特性を新しく学習したことにはなりません。

## GitHub Pagesでの計算

GitHub PagesはHTML、CSS、JavaScriptなどの静的ファイルを配信します。
このデモはPyodideのWebAssembly版Pythonを使い、配布ライブラリと同じNumPy、SciPy、OpenCVの処理をブラウザ内で実行します。
計算はWeb Workerに置き、画面の操作とは別に動かします。
テンプレートは必要な1ファイルだけを取得し、元画像は端末内のメモリから読み取ります。

計算結果には端末性能、初回のPython環境の取得時間、使用可能なメモリが影響します。
デモは各辺2048画素と32 MBまでを扱い、大規模な連続画像にはPython版を使います。
サイトは静的ですが、アクセスした利用者のPCで乱数生成とFFTを実行できるため、この手法のデモにサーバー側の計算は必要ありません。

公式仕様: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[Pyodide Web Worker](https://pyodide.org/en/stable/usage/webworker.html)、[Pyodideの対応パッケージ](https://pyodide.org/en/stable/usage/packages-in-pyodide.html)。
